# Threat Model – WebSocket + Nanoclaw Surface (2026-07-25)

Methodology: STRIDE-lite focused on the FastAPI WebSocket interface streaming orchestrator telemetry to the SPA plus the new read-only filesystem integration with the host Nanoclaw checkout.

## Assets
- Canonical telemetry event stream (orchestrator + sub-agent interactions)
- Agent roster and derived state cached client-side
- Backend service availability on host port 8000
- Configuration secrets (future real nanoclaw credentials)

## Trust boundaries
1. **Nanoclaw checkout → backend container**: read-only bind mount that exposes SQLite databases (`data/v2.db`, per-session `inbound/outbound.db`). Backend must not mutate these files.
2. **Backend → browser**: unauthenticated WebSocket over LAN.
3. **Operator shell → backend host**: environment variables / `.env` used for configuration.

## Entry points
- `/ws/events` WebSocket (bi-directional, though clients only read today)
- `/health` HTTP GET
- Read-only filesystem access to the Nanoclaw SQLite databases (bind-mounted path defined by `NANOCLAW_ROOT`)

## STRIDE analysis

| Threat | Scenario | Mitigation / status |
|--------|----------|---------------------|
| **Spoofing** | Malicious client connects to `/ws/events` and impersonates an allowed operator. | Endpoint currently unauthenticated → constrain deployment to trusted network/VPN. Add mTLS or token auth before WAN exposure; log session IDs. |
| **Tampering** | Poisoned telemetry enters via the Nanoclaw SQLite files (attacker modifies bind-mounted DB). | Mount is read-only; backend never writes. Validate rows via schema and treat mount as trusted host data (restrict filesystem perms). Consider hashing rows or verifying signatures if Nanoclaw adds them. |
| **Repudiation** | No audit trail for which client saw which events. | Structlog JSON logs connection counts today; add client identifiers (IP/session ID) before production. |
| **Information disclosure** | WebSocket leaks telemetry to eavesdroppers on shared network. | Require TLS termination (nginx/Envoy) for deployments; do not expose plain `ws://` outside LAN. |
| **Denial of Service** | Unlimited clients or malicious reconnect loops exhaust server resources. | `EventHub` caps concurrent clients (`NANOCLAW_MAX_CLIENTS`). Add per-IP throttling + exponential backoff on client reconnect. Consider message batching if telemetry volume spikes. |
| **Elevation of privilege** | Client sends data upstream to orchestrator via WebSocket. | Server ignores incoming frames; keep handler receive loop discarding data. Audit before adding bidirectional commands. |
| **Information disclosure (filesystem)** | Backend accidentally exposes Nanoclaw files over HTTP/WebSocket. | Mount is only accessed by the telemetry tailer; no static file serving. Document requirement to keep mount path secret and read-only. |

## Follow-ups
1. Introduce authenticated transport (mTLS or signed token) before exposing outside trusted LAN.
2. Add Syft-based SBOM generation + dependency scanning to CI (enforced by governance).
3. Implement per-IP connection tracking + rate limiting in `EventHub` (document mitigations once added).
4. Add runtime alerting if the Nanoclaw mount disappears or the SQLite tailer raises repeated errors (fallback to mock + operator notice).
