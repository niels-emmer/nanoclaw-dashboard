# Threat Model – WebSocket + Nanoclaw Surface (2026-07-25)

Methodology: STRIDE-lite focused on the FastAPI WebSocket interface streaming orchestrator telemetry to the SPA plus the new read-only filesystem integration with the host Nanoclaw checkout.

## Assets
- Canonical telemetry event stream (orchestrator + sub-agent interactions)
- Agent roster and derived state cached client-side
- Backend service availability on host port 8000
- Configuration secrets (future real nanoclaw credentials)

## Trust boundaries
1. **Nanoclaw checkout → backend container**: read-only bind mount that exposes SQLite databases (`data/v2.db`, per-session `inbound/outbound.db`). Backend must not mutate these files.
2. **Backend → browser**: unauthenticated WebSocket over LAN.
3. **Operator shell → backend host**: environment variables / `.env` used for configuration.

## Entry points
- `/ws/events` WebSocket (bi-directional, though clients only read today)
- `/health` HTTP GET
- `/api/config/file` HTTP GET — serves individual config file contents on demand for the instance-details browser (origin-validated → 403; path-traversal / non-`.md` / out-of-root → 404; content capped at 20 KB)
- `/api/backup/*` HTTP — backup/restore surface (since 2026-09-21): `GET /status`, `POST /` (create), `GET /` (list), `GET /download/{id}`, `POST /plan`, `POST /restore-script`. All origin-validated → 403; `GET /status` returns 200 with `enabled: false` in mock mode, the rest return **503** (`NANOCLAW_ENABLED=false`). An optional `NANOCLAW_BACKUP_TOKEN` shared secret (compared constant-time against the `X-Backup-Token` header) hardens the surface beyond the origin check. Backups read the read-only nanoclaw mount and write archives + restore scripts into the dashboard's writable `backups/` folder (mounted at `/backups` in Docker).
- Read-only filesystem access to the Nanoclaw SQLite databases (bind-mounted path defined by `NANOCLAW_ROOT`)

## STRIDE analysis

| Threat | Scenario | Mitigation / status |
|--------|----------|---------------------|
| **Spoofing** | Malicious client connects to `/ws/events` and impersonates an allowed operator. | Endpoint currently unauthenticated → constrain deployment to trusted network/VPN. Add mTLS or token auth before WAN exposure; log session IDs. |
| **Tampering** | Poisoned telemetry enters via the Nanoclaw SQLite files (attacker modifies bind-mounted DB). | Mount is read-only; backend never writes. Validate rows via schema and treat mount as trusted host data (restrict filesystem perms). Consider hashing rows or verifying signatures if Nanoclaw adds them. |
| **Repudiation** | No audit trail for which client saw which events. | Structlog JSON logs connection counts today; add client identifiers (IP/session ID) before production. |
| **Information disclosure** | WebSocket leaks telemetry to eavesdroppers on shared network. | Require TLS termination (nginx/Envoy) for deployments; do not expose plain `ws://` outside LAN. |
| **Denial of Service** | Unlimited clients or malicious reconnect loops exhaust server resources. | `EventHub` caps concurrent clients (`NANOCLAW_MAX_CLIENTS`) and uses a bounded ring buffer (`NANOCLAW_EVENT_BUFFER_SIZE`, default 100). Add per-IP throttling + exponential backoff on client reconnect. Consider message batching if telemetry volume spikes. |
| **Elevation of privilege** | Client sends data upstream to orchestrator via WebSocket. | Server ignores incoming frames; keep handler receive loop discarding data. Audit before adding bidirectional commands. |
| **Information disclosure (filesystem)** | Backend accidentally exposes Nanoclaw files over HTTP/WebSocket. | The mount is read-only and only accessed by the telemetry tailer; no static file serving. **Since 2026-09-05 the instance-details screen surfaces config markdown**: the `config_snapshot` event transmits the folder tree with file **metadata only** (no content), and individual file contents are served on demand via `GET /api/config/file` (origin-validated, `.md`-only, path-traversal-safe, 20 KB cap). These are agent instructions/governance, not credentials, but operators must keep secrets out of config markdown (or scrub them) before they are surfaced. Keep the mount path secret and read-only. |
| **Information disclosure (backup)** | A backup archive containing `.env` secrets is downloaded or left on disk. | `.env` inclusion is **opt-in and passphrase-encrypted** (openssl AES-256-CBC, PBKDF2) — never plaintext. Archives + scripts live in `backups/` (gitignored, mode-restricted 0600/0700, owned by the host user via `NANOCLAW_UID`/`NANOCLAW_GID`). The download endpoint is origin-validated like `/api/config/file` and can require `NANOCLAW_BACKUP_TOKEN`. Restore scripts prompt for the passphrase on the host. Agent backups are configuration-only — working data (repos/projects) and files over 10 MiB are excluded, reducing the disclosure surface. |
| **Tampering (backup)** | A modified archive is restored, injecting malicious rows/files into the nanoclaw install. | Every file in the archive carries a sha256 in `manifest.json`; the restore script verifies checksums before applying (detects transit corruption — note the manifest travels inside the archive, so a fully crafted archive carries a matching manifest; the archive is only as trusted as its origin). Restore is a **host-side script** the operator runs deliberately — the dashboard never writes to the nanoclaw mount. The script snapshots current state before applying, refuses schema downgrades, rejects traversal archive members before extraction, and restarts the service on failure. |
| **Elevation of privilege (restore)** | The restore script is tricked into writing outside the nanoclaw root (path traversal in archive member names). | Backup ids are server-generated and regex-validated (`backup-YYYYMMDD-HHMMSS[-N]`) before any filesystem resolution — traversal ids return 404. The backend extracts with a manual safe-extract (Python 3.11-compatible) that rejects absolute paths, `..` traversal, symlinks/hardlinks, and device files; the host-side script rejects the same member types (`tar -tvzf` pre-check) before extracting into a fresh temp dir, and only copies known relative paths (`groups/`, `memory/`, `container/`, `data/v2-sessions/`, `.env`) under the resolved nanoclaw root. |
